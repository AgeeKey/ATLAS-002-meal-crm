## 2. Анализ компонента 1: Дашборд (`frontend/src/routes/_layout/index.tsx`)

### 2.1 Текущая структура данных и логика
- **Используемые запросы (TanStack React Query v5):**
  1. `ClientsService.readClients({ query: { limit: 500, skip: 0 } })` — ключ `["clients", "list", 500]`
  2. `PackagesService.readPackages({ query: { status: "active", limit: 500, skip: 0 } })` — ключ `["packages", "list", "active", "dashboard"]`
  3. `PackagesService.getTodaysDeliveryCount()` — ключ `["deliveries", "today"]`
- **Вычисляемые бизнес-метрики (хук `useMemo`):**
  - `activeClients`: клиенты со статусом `active` (например, 48).
  - `pausedClients`: клиенты со статусом `paused`.
  - `packagesEndingSoon`: активные пакеты, где `end_date` попадает в окно ближайших 7 дней (`now <= endDate <= nextWeek`).
  - `totalDebt` & `debtClients`: сумма `pkg.debt` по всем активным пакетам с долгом и объединение с клиентами в статусе `debt`.
  - `todaysDeliveries`: количество выдач питания курьерам на сегодня (`todaysDeliveryData.count`).
  - `mealBreakdown`: распределение 3X vs 5X (количество, процент от общего числа активных пакетов) и расчет дневной загрузки кухни:
    $$\text{totalDailyMeals} = (\text{count3X} \times 3) + (\text{count5X} \times 5)$$

### 2.2 Анализ визуального слоя
- **Hero-карточка «Доставки на сегодня»:**
  - Оформлена с акцентной изумрудной рамкой `border-emerald-500/30` и фоном `bg-emerald-500/5`.
  - Сохраняет обязательный селектор `data-testid="todays-deliveries-value"`.
- **KPI-сетка:**
  - 4 карточки: «Доставки на сегодня», «Активные клиенты», «Заканчивающиеся пакеты (до 7 дней)», «Сумма долгов».
- **Рабочая зона менеджера (Action Center):**
  - Левая колонка (7/12): Блок «Требуют внимания менеджера» с двумя списками:
    1. Срочные продления (пакет, оставшиеся дни, кнопка перехода «Продлить»).
    2. Должники (пакет, сумма долга с коралловым акцентом, кнопка перехода «Оплата»).
  - Правая колонка (5/12): Блок «Структура рационов питания» с полосами прогресса 3X / 5X и плашкой оценки объема производства кухни (`~N готовых блюд в день`).

## 5. Анализ API, Hooks и типизации (`frontend/src/client/`)

### 5.1 Генерация и структура
- Клиент сгенерирован библиотекой `@hey-api/openapi-ts` на основе OpenAPI спецификации бэкенда FastAPI.
- Все методы разделены по статическим классам сервисов:
  - `ClientsService`:
    - `readClients({ query: { status, skip, limit } })`
    - `readClient({ path: { id } })`
    - `createClient({ body: CrmClientCreate })`
    - `updateClient({ path: { id }, body: CrmClientUpdate })`
    - `createClientNote({ path: { id }, body: CrmNoteCreate })`
  - `PackagesService`:
    - `getTodaysDeliveryCount()`
    - `readPackages({ query: { status, skip, limit } })`
    - `readPackage({ path: { id } })`
    - `createPackage({ body: CrmPackageCreate })`
    - `updatePackage({ path: { id }, body: CrmPackageUpdate })`
    - `createDelivery({ path: { id }, body: CrmDeliveryCreate })`
    - `createFreeze({ path: { id }, body: CrmFreezeCreate })`
    - `createExtension({ path: { id }, body: CrmExtensionCreate })`
    - `readPackagePayments`, `readPackageDeliveries`, `readPackageFreezes`, `readPackageExtensions`
  - `PaymentsService`:
    - `createPayment({ body: CrmPaymentCreate })`

### 5.2 Модели данных TypeScript
- **`CrmPackageDetail`:**
  - `id: string`, `client_id: string`, `meal_type: '3X' | '5X'`, `status: 'active' | 'completed' | 'paused'`
  - `total_days: number`, `days_used: number`, `days_remaining: number`
  - `freeze_days: number`, `extension_days: number`, `extension_added_price: number`
  - `price: number`, `paid_amount: number`, `debt: number`
  - `start_date: string`, `end_date?: string | null`
  - `deliveries: CrmDeliveryPublic[]`, `freezes: CrmFreezePublic[]`, `extensions: CrmExtensionPublic[]`, `payments: CrmPaymentPublic[]`
- **`CrmClientDetail`:**
  - `id: string`, `name: string`, `phone: string`, `address?: string | null`, `email?: string | null`, `status: ClientStatus`, `notes?: string | null`, `contact_extra?: string | null`
  - `packages: CrmPackageDetail[]`
  - `client_notes: CrmNotePublic[]`

### 5.3 Инвалидация кэша React Query
При любых мутациях (добавление пакета, проведение оплаты, создание доставки, заморозка, продление) на фронтенде настроена надежная каскадная инвалидация:
```typescript
onSettled: () => {
  queryClient.invalidateQueries({ queryKey: ["clients"] })
  queryClient.invalidateQueries({ queryKey: ["packages"] })
  queryClient.invalidateQueries({ queryKey: ["deliveries"] })
}
```
Это гарантирует, что дашборд, список клиентов и детальная карточка обновляются синхронно и показывают свежие данные без перезагрузки страницы.
